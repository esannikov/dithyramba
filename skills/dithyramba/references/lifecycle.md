# Library lifecycle

Use the installed `dithyramba` command. Add `uv run` only when operating from a
source checkout whose virtual environment is intentionally in scope.

## Discover and describe

```bash
dithyramba library list --data-home /absolute/runtime-root --json
dithyramba library describe \
  --library library-id \
  --data-home /absolute/runtime-root \
  --json
dithyramba library doctor \
  --library library-id \
  --data-home /absolute/runtime-root \
  --json
```

`describe` reconstructs operator state without returning source text. `doctor`
checks layout, schema, integrity, and local SQLite capabilities.

## Build a Library

```bash
dithyramba library init "Research name" \
  --source-root /absolute/source-root \
  --data-home /absolute/runtime-root \
  --json

dithyramba collection add "Primary sources" \
  --root /absolute/source-root \
  --kind corpus \
  --library library-id \
  --data-home /absolute/runtime-root
```

Use the `library_id` returned by `library init`; it is generated by the core and
must not be guessed from the display name. Likewise, use the `collection_id`
returned by `collection add` in later commands.

Create a default-deny policy before recall. Use `dithyramba access-policy
--help` and the repository's `docs/HOW_TO_USE.md` for the current policy input
shape; do not invent an allow-all policy.

```bash
dithyramba index \
  --collection primary \
  --library library-id \
  --data-home /absolute/runtime-root

dithyramba collection freeze \
  --collection primary \
  --library library-id \
  --data-home /absolute/runtime-root
```

The source root is read-only input. The data home contains the SQLite Library,
derived text, audit log, backups, and other rebuildable runtime artifacts.

## Refresh incrementally

Run `index` again against the same Collection. Dithyramba reuses unchanged
content and records changed source versions. Freeze a new snapshot after the
refresh; never overwrite the previous snapshot identity.

## Inspect and read

```bash
dithyramba recall "research question" \
  --library library-id \
  --data-home /absolute/runtime-root \
  --help

dithyramba lens library \
  --library library-id \
  --data-home /absolute/runtime-root
```

Use `--help` before supplying recall scope because the exact snapshot, policy,
and Collection IDs are deliberate security boundaries.

## Back up

```bash
dithyramba backup \
  --library library-id \
  --data-home /absolute/runtime-root \
  --output-directory /absolute/backup-parent
```

A backup is a portable bundle outside the live Library. Verify it before any
migration. Restore must target a new empty location and must never overwrite a
live Library.

## Diagnose safely

1. Capture `library describe --json` and `library doctor --json`.
2. Record the exact command, version, Library ID, data home, and error.
3. Reproduce on a disposable Library when possible.
4. Do not edit SQLite directly or remove caches as a first response.
5. Preserve the failed processing run and audit trail until the cause is known.
